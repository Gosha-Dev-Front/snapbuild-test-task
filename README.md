# Snapbuild — тестовое задание

## О проекте

Самостоятельная React-реализация лендинга Снэпбилда. Она сохраняет визуальную систему исходного сайта и развивает продуктовый рассказ пятью новыми секциями. В проекте нет UI-kit или backend: интерфейс, схемы и состояния собраны на React и CSS.

## Demo

[https://gosha-dev-front.github.io/snapbuild-test-task/](https://gosha-dev-front.github.io/snapbuild-test-task/)

Vite использует относительный `base`, поэтому проект работает в подпапке GitHub Pages и после refresh.

## Local development

```bash
npm install
npm run dev
npm run build
```

## Стек

React, TypeScript, Vite, CSS. Типографика задаётся стеком `TT Commons Pro`, `Segoe UI`, Arial: первый шрифт используется оригинальным сайтом, а системные варианты служат максимально близким fallback, если публичный font-файл недоступен.

## Добавленные секции

1. «От идеи до готовой кампании» — доступный tabs/switcher для Marketing, Product, Sales и HR.
2. «Подключите бренд один раз» — связанный pipeline от источника до материалов.
3. «Встраивается в существующий процесс» — техническая карта интеграций.
4. «Одна идея — десятки готовых материалов» — трансформация запуска в пять форматов.
5. «Запрос демо» — controlled form с inline-ошибками, loading и полноценным success state.

## Анализ исходного дизайна

Подробности находятся в `DESIGN_AUDIT.md`. Ключевые наблюдения: светло-серая базовая поверхность, чёрные функциональные акценты, крупная плотная типографика, контейнер около 1200 px, большие вертикальные интервалы, белые интерфейсные панели с радиусом 16 px. Композиция опирается на продуктовые mockup, переключатели и таблицы.

## Воспроизведённые части

Перенесены header/navigation, hero с mockup редактора, социальный контекст, «одна платформа», пять типов контента, comparison, безопасность, roadmap, FAQ, финальный CTA и footer. Содержимое адаптировано без фиктивных отзывов и неподтверждаемых метрик.

## Технические решения

Vite выбран ради простой статической сборки и публикации. Крупные смысловые блоки разделены компонентами; локальный state используется только для tabs, accordion и формы. Responsive построен на fluid typography и двух структурных breakpoint: 900 и 600 px. Таблица прокручивается внутри собственного контейнера и не создаёт overflow страницы.

## GitHub Pages

1. Выполнить `npm run build`.
2. Опубликовать содержимое `dist` через GitHub Pages или workflow GitHub Actions.
3. В Settings → Pages выбрать GitHub Actions/ветку публикации.

## AI

Codex использовался для анализа структуры проекта, первичных вариантов компонентов, рефакторинга, responsive-проверки, подготовки тестовых сценариев и review кода. Итоговые решения, дизайн и код проверялись и корректировались вручную.

## Что можно улучшить

Добавить visual regression и e2e-тесты, провести расширенный accessibility-аудит, заменить системно близкий шрифт на лицензированный исходный ассет и точнее воспроизвести оригинальные продуктовые иллюстрации.
